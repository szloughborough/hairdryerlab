# 内容上线检查表（Pre-Publish Gate）

> **每篇文章发布前必须逐条过完本表。未通过不得发布。**
> 来源：融合了 handoff skill 包的可借鉴规则（标注 `[借鉴]`）+ 我们自有的差异化标准。
> 配套：《内容结构标准.md》《技术SEO与信息架构规划.md》《借鉴分析与AI搜索优化标准.md》

---

## 使用方法

1. 写完草稿 → **先跑自动检查器**：
   ```
   python _scripts/check_article.py deliverables/drafts/<文章>.mdx
   ```
   输出见 `analysis/_compliance.txt`。自动检查覆盖：H1 数、导语词数、H2 含核心实体比例、带单位数字数、表格行数、FAQ 条数与答案词数、frontmatter 同步、联盟披露、证据等级、价格核对日期、旁观者措辞命中、aggregateRating / Offer 占用、内链数。
2. 自动检查通过后 → 人工过本表余下条目（尤其 A 骨架覆盖、B answer-first、D 不虚构）
3. 任何一条 `[ ]` 未勾选 → 修完再发
4. 涉及计数的项在文末记录数字（便于跨文章对账）
5. **【待实测】占位符未清零不得发布**

---

## A. 页面结构

- [ ] **恰好一个 H1**，含页面核心实体/首要关键词 `[借鉴]`
- [ ] H1 后紧跟 **90–110 词导语**（即首屏结论卡），直接给结论 `[借鉴]`
- [ ] 已按《内容结构标准》对应类型的固定骨架排布，`[新增]` 区块未遗漏
- [ ] 商业页 **八维评测标准**已覆盖，**第 1 维（耐用性）与第 2 维（安全温控）未省略**
- [ ] 每个 H2 **自包含**（脱离上下文能独立表达完整语义）
- [ ] 每个 H2 含**页面核心实体或其自然语义变体**
      ❌ `## Why it matters` / `## 总结` → ✅ `## Why durability matters for Dyson alternatives`
- [ ] 每个 H2 带稳定 `id` 锚点
- [ ] 无空标题、无「更多信息」类占位标题

**计数记录**：H1 = ___ ｜ H2 = ___ ｜ 导语词数 = ___

---

## B. AI / 大模型可抽取性

- [ ] **每个 H2 下的第一句话就是该问题的答案**（answer-first，无铺垫式开头）
- [ ] **所有数字都带单位与测量条件**
      ❌ `very quiet` → ✅ `62 dB（距出风口 30 cm，背景 34 dB）`
- [ ] 对比数据用 `<table>`、规格用 `<dl>`、步骤用 `<ol>`（结构化优先于长段落）
- [ ] 关键结论用定义式句式（「X 是……」「X 指……」）
- [ ] **每段一个主张**（便于按块检索命中）
- [ ] 正文与 FAQ **不依赖客户端 JS 渲染、不 lazy-load**
- [ ] 关键文字**不在图片里**（参数/结论/FAQ 必须是可选中的文字）
- [ ] 可见 `Last updated` 就位，并同步 `dateModified`

**计数记录**：带条件与单位的数字个数 = ___

---

## C. FAQ

- [ ] 数量 **≥5 条**（Pillar/榜单 5–8；其他 5）
- [ ] **每条都来自真实调研**（PAA / 评论提问库 / 关键词数据），附来源记录
- [ ] 每条答案 **≤100 词**
- [ ] 每条**第一句直接回答问题**
- [ ] 内容**存在于 DOM**（折叠可以，但不得点击后才请求）
- [ ] `FAQPage` JSON-LD 与可见文字**逐字一致**（仅空白归一化差异）
- [ ] 未出现「不承诺富媒体结果」的相反表述（不声称会出富结果）

**计数记录**：FAQ 条数 = ___ ｜ 最长答案词数 = ___ ｜ schema 与可见一致 = 是/否

---

## D. 信任与合规

- [ ] **联盟披露可见**（页首或价格区 + 全站页脚）—— **独立联盟站必做，不可省略**
- [ ] **主动说明研究方法与数据来源**（如「我们分析了 8,261 条 Amazon.ca 评论」）—— 这是我们的资产
- [ ] **证据等级标注**：实测 / 评论分析 / 买家反馈 / 厂商宣称，逐条可辨
- [ ] **不虚构**专业头衔、证书、从业年限；作者署名只陈述真实做过的事
- [ ] **价格**：显示数字时标注核对日期（如 `C$99.99（2026-10-02 核对）`）；无验证价用 `Check current price on Amazon`
- [ ] 每个推荐产品都有**缺点/不适合谁**
- [ ] 未实测的项目写「我们尚未测试」，**不编造数字**
- [ ] 【待实测】占位符**全部填完**（未填完不发布）

---

## E. 结构化数据

- [ ] **不输出 `Offer`**（我们不是卖家，价格不由我们控制）
- [ ] **不输出 `aggregateRating`**（除非评分来自我们自己的实测）
- [ ] Amazon 星级只作**可见文字**呈现，并在同页注明来源
- [ ] 未编造 review / 评分 / 价格 / 可用性 / `priceValidUntil`
- [ ] Breadcrumb 结构化数据**独立于** Product 资格
- [ ] 每页**恰好一个 canonical**，不含 query/fragment
- [ ] Schema 已通过 Rich Results Test / Schema 校验

**计数记录**：Offer 数 = 0 ｜ aggregateRating 数 = 0

---

## F. 内链与联盟链接

- [ ] 每页 **≥3 条站内内链**，锚文本用目标关键词、自然变化
- [ ] 信息页 → 商业页的导流内链就位
- [ ] 评测 ↔ 对比 ↔ 榜单 互链就位
- [ ] Pillar 链出本集群所有页；集群页回链 Pillar
- [ ] 联盟链接密度合规（每 500 词 ≤1–2 个），不堆砌、不隐藏
- [ ] 断链 = 0

**计数记录**：内链 = ___ ｜ 联盟链 = ___ ｜ 断链 = ___

---

## G. 🔴 禁止项扫描（借鉴包里「不能照搬」的部分，必须反向执行）

> 这四条是 handoff 包为**品牌自营站**设的规则，**对我们必须反着做**。逐条确认：

- [ ] **确认产品页有联盟披露**（不可像品牌站那样省略）
- [ ] **确认未出现旁观者措辞**：`the listing describes` / `the product page includes` / `according to Amazon` / `the source listing`
      （但保留「我们分析了…」这类**以我们为主体**的研究陈述）
- [ ] **确认未把 Amazon/零售商当作卖点叙述者**（零售商只在说明购买渠道时出现）
- [ ] **确认没有为主关键词套用「品牌+品类」映射**（我们打非品牌词）

## H. 计数对账 `[借鉴]`

- [ ] 计划页数 = 实际上线页数
- [ ] H1 数 = canonical 数 = 页面数
- [ ] FAQ 覆盖页数、schema 与可见文字一致数已统计
- [ ] 内链数、断链数已统计（断链 = 0）
- [ ] **不因「页面已生成」就判定完成**
